## Fix first (ranked by errors removed x ease)

| # | Fix | Category | Errors it targets | Ease (3 = easy) | Score |
|---|---|---|---|---|---|
| 1 | Ask the model for each tax line separately and add them up in code | TAX_INTERPRETATION | 2 | 2 | 4 |

1. **Ask the model for each tax line separately and add them up in code.** Extend the internal LLM schema with tax_lines: [{label, amount}]; set tax_total = sum(tax_lines) in code. The output schema is unchanged. Removes the model's arithmetic from the loop.
2. **State the discount-sign rule more forcefully, and give the repair prompt the actual arithmetic.** The v1 prompt already says discounts are negative, but the model still returned +450, and the generic repair message didn't fix it. Make the repair prompt say: lines sum to X, tax Y, total Z, gap D. Check signs of discount rows and re-add the tax lines.
3. **Tighten the totals tolerance** (validation, not extraction). Use e.g. max(1.00, 0.05% of total), so a 20-rupee error on a 23,000-rupee invoice gets flagged. It doesn't fix errors, but it raises validation recall.
